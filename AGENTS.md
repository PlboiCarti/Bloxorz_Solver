# AGENTS.md

## Project

Bloxorz AI solver (CSC14003 course project). Python 3.12, managed with `uv`.

Work is split across branches, one per workstream. Do not edit another team's
module:

- `engine` — Game Engine (Board/State/Action, rules, advanced tiles) → owns `game/`
- `solver` — search algorithms (BFS/DFS/UCS/A\*) → owns `solvers/`
- `gui` — GUI + integration → owns `gui/`

## Current state

The repo is an empty scaffold: every `.py`, `levels/*.json`, and
`experiments/results.csv` is 0 bytes, and all test files are empty. Check for
existing content before assuming an implementation exists.

## Commands

- Sync deps: `uv sync --dev`
- Run tests: `uv run pytest` (run from repo root)
- Single test: `uv run pytest tests/test_bfs.py::test_name`
- Regenerate deps: `uv export --format requirements-txt > requirements.txt`
  (`requirements.txt` is autogenerated — never hand-edit it.)

`pyproject.toml` installs `bloxorz-solver` from `src/bloxorz_solver/`, but the
real code lives in top-level packages (`game/`, `solvers/`, `gui/`,
`experiments/`). Tests import those top-level packages, so pytest needs the repo
root on `sys.path`; CI sets `PYTHONPATH=<repo root>`. There is no pytest config
and zero tests, so bare `pytest` exits 5 — CI treats exit 5 as "no tests", not
failure.

## Conventions / gotchas

- `main.py` (repo root, empty) is the intended program entrypoint.
- Engine API contract is fixed in `docs/api.md`; module boundaries/interfaces in
  `docs/Mô tả công việc.md`. Do not change interfaces without team agreement.
- Levels are JSON in `levels/` and must be reusable across all solvers.
- pre-commit config is at the non-standard `.github/pre-commit.yaml`, so run it
  explicitly: `pre-commit run --config .github/pre-commit.yaml --all-files`.
- `GEMINI.md` rules still apply: record project-wide decisions as one-line
  bullets in `docs/engine.md`; also add any new dep to `requirements.txt`.
