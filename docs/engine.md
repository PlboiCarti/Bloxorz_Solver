# engine

- dùng python 3.12
- quản lí bằng uv cho python project
- Coordinates are `(row, col)`, origin top-left; block anchor is the top-left occupied cell.
- Orientation transitions are a data table keyed by `(Orientation, Action)`.
- Illegal moves (off-board or onto void) return `None` from `transition`; falling is never a state.
- The goal cell supports a lying block; win only when standing on the goal and not split.
- `legal_actions` is derived from `transition` and does not treat the goal as terminal.
- `Action` includes `SWITCH_CUBE`, which is never legal in the core.
- `State` is a frozen, slotted dataclass with `to_dict`/`from_dict` for the Three.js export.
- Level format is JSON with a grid as an array of strings; advanced tiles are parsed but not interpreted by TV1.
- `src/` is removed; the single package layout uses the top-level `game/`.
- Tooling: pytest with `pythonpath = ["."]`, ruff default rules, pyright `standard`; `requirements.txt` comes from `uv export`.
- `step_cost` returns `1.0` until the team fixes the cost function.
- `State.occupied_cells()` and the module-level `occupied_cells(state)` helper both return the occupied cells for all three orientations.
- `game/__init__.py` exports the public names: `Action`, `Board`, `BridgeStates`, `Cell`, `Engine`, `Orientation`, `State`, `TileType`, `load_board`, `occupied_cells`, `parse_board`.
- The level loader raises `ValueError` for grid/start/goal errors and `TypeError` for non-list `bridges`/`switches` or a non-object JSON root.
- An integration smoke test in `tests/test_transition.py` solves `levels/level1.json` with a BFS written inside the test, using only the Engine API.
- Level JSON schema (Section 4.4) is confirmed; advanced tiles are parsed but treated as plain floor by the core (confirmed, loader does not reject them).
- `BridgeStates` and `step_cost = 1.0` are confirmed temporary placeholders: TV2 finalizes `bridge_states`, the team finalizes the UCS/A\* cost function.
- Cross-stream dependencies (TV2/TV3/TV4/TV5) are summarized in `docs/api.md` Section 6.7.
- GUI API contract document created at `docs/gui_api.md` detailing Engine & Solver interfaces, state machine, and replay specifications for TV5.
- `BridgeStates` được TV2 chốt biểu diễn là `tuple[bool, ...]`, phần tử thứ i ứng với cầu thứ i trong danh sách `bridges` của màn chơi (`True` là mở, `False` là đóng).
- Ô `FRAGILE` (`F`) chỉ làm rơi khối khi khối nguyên vẹn đứng thẳng (`STANDING`); khối nằm hoặc khối lập phương $1\times1\times1$ được nâng đỡ an toàn.
- Ô `BRIDGE` (`B`) chỉ nâng đỡ khối khi cầu đang mở (`True`); cầu đóng hoạt động tương tự ô `VOID`.
- Công tắc `soft` (`o`) kích hoạt khi bất kỳ phần nào của khối đè lên; công tắc `heavy` (`x`) và `split` (`P`) chỉ kích hoạt khi khối nguyên vẹn đứng thẳng.
- Các chế độ cầu gồm `toggle`, `permanent_open`, `permanent_closed` được cập nhật thuần túy vào `bridge_states`.
- Khi giẫm lên công tắc `split` (`P`), khối tách thành hai khối $1\times1\times1$ tại `split_cells`, điều khiển cube1; `SWITCH_CUBE` chuyển đổi khối điều khiển.
- Hai khối lập phương $1\times1\times1$ khi di chuyển đến 2 ô kề nhau sẽ tự động hợp nhất (`merge`) thành khối $1\times1\times2$ (`HORIZONTAL` hoặc `VERTICAL`).
- TV2 hoàn thiện và kiểm thử giải thành công toàn bộ 9 màn chơi từ `levels/level2.json` đến `levels/level10.json`.
