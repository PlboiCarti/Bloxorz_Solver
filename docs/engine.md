# engine

- dùng python 3.12
- quản lí bằng uv cho python project
- Coordinates are `(row, col)`, origin top-left; block anchor is the top-left occupied cell.
- Orientation transitions are a data table keyed by `(Orientation, Action)`.
- Illegal moves (off-board or onto void) return `None` from `transition`; falling is never a state.
- The goal cell supports a lying block; win only when standing on the goal and not split.
- `legal_actions` is derived from `transition` and does not treat the goal as terminal.
- `Action` includes `SWITCH_CUBE`, which is never legal in the core.
- `State` is a frozen, slotted dataclass with `to_dict`/`from_dict` for the Three.js export.
- Level format is JSON with a grid as an array of strings; advanced tiles are parsed but not interpreted by TV1.
- `src/` is removed; the single package layout uses the top-level `game/`.
- Tooling: pytest with `pythonpath = ["."]`, ruff default rules, pyright `standard`; `requirements.txt` comes from `uv export`.
- `step_cost` returns `1.0` until the team fixes the cost function.
- `State.occupied_cells()` and the module-level `occupied_cells(state)` helper both return the occupied cells for all three orientations.
- `game/__init__.py` exports the public names: `Action`, `Board`, `BridgeStates`, `Cell`, `Engine`, `Orientation`, `State`, `TileType`, `load_board`, `occupied_cells`, `parse_board`.
- The level loader raises `ValueError` for grid/start/goal errors and `TypeError` for non-list `bridges`/`switches` or a non-object JSON root.
- An integration smoke test in `tests/test_transition.py` solves `levels/level1.json` with a BFS written inside the test, using only the Engine API.
- Level JSON schema (Section 4.4) is confirmed; advanced tiles are parsed but treated as plain floor by the core (confirmed, loader does not reject them).
- `BridgeStates` and `step_cost = 1.0` are confirmed temporary placeholders: TV2 finalizes `bridge_states`, the team finalizes the UCS/A\* cost function.
- Cross-stream dependencies (TV2/TV3/TV4/TV5) are summarized in `docs/api.md` Section 6.7.
- GUI API contract document created at `docs/gui_api.md` detailing Engine & Solver interfaces, state machine, and replay specifications for TV5.
- GUI contract v3: `Engine.transition` returns a `TransitionResult` (status `ok`/`fall`/`illegal`, `is_goal`, `reason`); engine/`docs/api.md`/tests updates pending (TV1/TV2).
- GUI contract v3: `/solve` is a synchronous request with a hard server-side timeout (default 10 s); no job API.
- GUI contract v4: TV2 advanced-tile semantics confirmed (bridge/switch schema + validation, switch activation, fragile support, split/merge, fall rules) in `docs/gui_api.md` §3.1–§3.3.
- `bridge_states` final representation: ordered tuple aligned with `Board.bridges`, initialized from each bridge's JSON `initial` ("open"/"closed"); `docs/api.md` §6.1 is no longer TEMPORARY.
- New transition reason codes: `bridge_closed` (fall) and `cube_collision` (illegal); A\* heuristic in split mode fixed at `h = 0`.
- `docs/api.md` §6.1/§6.4/§6.5/§6.6 are now all CONFIRMED: advanced mechanics implemented in `game/tiles.py`, `game/switches.py`, `game/split_block.py`; the `_roll`/`_cells_supported`/`_apply_tile_effects` hooks are real (no `# TODO(TV2)`).
- Bridge/switch config is deep-validated when the `Engine` is built (`build_mechanics`); mismatches with the grid (missing `id`, wrong `cell`/`type`, unknown bridge target, bad `initial`/`mode`) raise `ValueError`.
- `SWITCH_CUBE` is legal only in split mode; soft switches trigger on any contact while heavy/split switch and fragile breaking require the intact 1x1x2 block standing; split switch yields two 1x1 cubes with automatic merge.
- Ô `FRAGILE` (`F`) chỉ làm rơi khối khi khối nguyên vẹn đứng thẳng (`STANDING`); khối nằm hoặc khối lập phương $1\times1\times1$ được nâng đỡ an toàn.
- Ô `BRIDGE` (`B`) chỉ nâng đỡ khối khi cầu đang mở (`True`); cầu đóng hoạt động tương tự ô `VOID`.
- Các chế độ cầu gồm `toggle`, `permanent_open`, `permanent_closed` được cập nhật thuần túy vào `bridge_states`.
- Khi giẫm lên công tắc `split` (`P`), khối tách thành hai khối $1\times1\times1$ tại `split_cells`, điều khiển cube1; `SWITCH_CUBE` chuyển đổi khối điều khiển, và hai khối kề nhau tự động hợp nhất (`merge`) thành khối $1\times1\times2$ (`HORIZONTAL` hoặc `VERTICAL`).
- Levels `levels/level2.json`–`level10.json` added (levels 1–10 complete); TV2 tested solving all 9 levels.
- `Engine.transition` now returns `TransitionResult` (`TransitionStatus` ok/fall/illegal + `is_goal` + `reason`), exported from `game`; fall reasons (`off_board`, `void`, `bridge_closed`, `fragile_standing`) resolved by `support_failure` in `game/tiles.py` with precedence off_board → void → bridge_closed → fragile_standing.
- `legal_actions` filters on `transition(...).status is TransitionStatus.OK`; `_cells_supported` replaced by `_support_failure`.
- `Board` gained `grid_raw` (original JSON row strings for the HTTP layer), public `Bridge`/`Switch`/`SwitchTarget` dataclasses, and derived `bridge_at`/`switch_at` views; `bridges`/`switches` fields still hold the raw metadata records, deep-validated at `Engine` construction.
- Solvers implemented in `solvers/` (BFS, DFS, UCS, A* + `base_solver`/`search_result`), each exposing `solve(initial_state, engine) -> SearchResult` and re-exported as `solve_bfs`/`solve_dfs`/`solve_ucs`/`solve_astar`; A* uses `h = ceil(manhattan/2)`, `h = 0` in split mode.
- `server.py` FastAPI adapter added with `GET /levels`, `GET /levels/{name}`, `POST /transition`, `POST /solve` and the `{"error": {"code", "message"}}` envelope; `fastapi`/`uvicorn` are runtime deps, `httpx` is a dev dep for `TestClient`.
